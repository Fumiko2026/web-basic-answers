## Q1. インターネットとは

**問題:** 「インターネット」と「Webブラウザで見るホームページ」は同じものですか？違うとすれば、どう違いますか？

**回答:**

同じではありません。
インターネットは、世界中のコンピュータやネットワークを共通のルールで繋いだ例えれば道路網のような巨大なネットワークのことです。
共通のルールとは、通信の決まりであるプロトコルのことです。代表はTCP/IPで、データの送り先や宛先の決め方を定めています。
ホームページは、その道路を使って運ばれる例えれば荷物のうちの一つです。他の荷物（メールなど）も、同じ道路を通ります。サーバーとブラウザで動きます。
日常生活では、ホームページはブラウザで見ます。メールやオンラインゲームもインターネットを使っていますが、WEBではありません。

## Q2. IPアドレスとポート番号

**問題:** このプロジェクトではフロントエンドを `localhost:5173`、バックエンドを `localhost:8080` で起動しています。

- `localhost`とは何を指しますか？
- `:5173` や `:8080` のようなポート番号はなぜ必要ですか？

**回答:**

localhostとは、自分自身のコンピューターを指す特別なホスト名です。IPアドレスで言うと127.0.0.1(ループバックアドレス)に対応します。ネットワークの外には出ず、同じPC内で通信が完結します。
開発中は、自分のPCで動かしているサーバーにアクセスするために使います。

ポート番号が必要な理由

IPアドレスは「どのコンピューターか」を指しますが、１台のPCでは複数のプログラムが同時に通信しています。ポート番号は「そのPCのどのプログラムか」を区別する番号です。住所（IP)が建物、ポート番号は部屋番号というイメージです。

このプロジェクトでは、同じlocalhost上で
・5173（フロントエンド）
・8080（バックエンド）

と別々に動くため、ポート番号で振り分けています。同じポートを２つのプログラムが同時に使うことはできません。

## Q3. DNS

**問題:** ブラウザのアドレスバーに `https://www.example.com` と入力してからページが表示されるまでに、DNSはどのような役割を果たしますか？

**回答:**

DNS（Domain Name　System)の役割は「ドメイン名」をIPアドレスに変換することです。
コンピュータ同士はIPアドレス（93.184.216.34など）で通信しますが、人間が覚えやすいのはwww.example.comのような名前です。DNSはその対応表（電話帳）の役割を果たします。DNSによる名前解決が終わって初めて、サーバーへの接続が始まります。

流れはこうです。
１　https://www.example.comと入力する

２　ブラウザが「www.example.comのIPアドレスは？」とDNSサーバーに問い合わせる。

３　DNSサーバーが93.184.216.34のようなIPアドレスを返す。

４　ブラウザがそのIPアドレスのサーバーに接続し、ページのデータを受け取る。

５ページが表示される。

## Q4. HTTPとは

**問題:** HTTPとは何の略で、どのような役割を持つものですか？「プロトコル」という言葉の意味も含めて説明してください。

**回答:**

HTTP：HyperText Transfer Protocolの略です。

プロトコルとは、通信のルールのことです。人間同士でも言語や話し方が合わないと会話できません。コンピュータ同士も「どんな形式で、どんな順番でやり取りするか」を決めておく必要があり、その取り決めがプロトコルです。

HTTPの役割

WEBブラウザとWEBサーバーの間で、HTML・画像などのデータをやり取りするためのルールです。

・リクエスト：ブラウザがサーバーに「このページをください」とリクエストを要求する。

・レスポンス：サーバーが結果を返す（コード200 OK。404 Not Foundなど）＋データ本体

このプロジェクトでも、フロントエンドがバックエンドのLocalHost：8080にHTTPリクエストを送ってデータを取得しています。

## Q5. HTTPとHTTPSの違い

**問題:** HTTPとHTTPSの違いは何ですか？なぜ現在のWebサイトはほぼすべてHTTPSを使用していますか？

**回答:**

違いは、HTTPSは、HTTPの通信を暗号化したものです。

 HTTPSの「S」は、Secure（安全）の意味で、HTTPにTLS（SSL)という暗号化の仕組みを組み合わせています。

 HTTPSが必要な３つの保護
 １　盗聴の防止：パスワードやクレジットカードの番号を盗み見られない

 ２　改ざんの防止：通信途中でデータが書き換えられない

 ３　なりすましの防止：証明書により本物のサーバーと通信していると確認できる。

そのため、
・公共Wifiなどで盗聴リスクがあるため

・ブラウザがHTTPサイトに「保護されていない通信」と警告を出すようになったため

・無料の証明書が普及し、導入しやすくなったため

・検索エンジンもHTTPSを評価し、HTTP/2などの新しい機能もHTTPS前提のものが多いため


## Q6. リクエストとレスポンス

**問題:** Webにおける「リクエスト」と「レスポンス」の関係を、日常生活の例えを使って説明してください。

**回答:**

レストランの注文に例えます。
リクエスト：お客さん（ブラウザ）が店員に「カレーをください」と注文すること

レスポンス：厨房（サーバー）が料理を作り、店員がお待たせしましたと持ってくること。

必ず「注文→提供」の順で、お客さんから話しかけない限り、店は料理を出しません。WEBも同じで、ブラウザが先にリクエストを送り、サーバーがレスポンスを返します。

## Q7. HTTPメソッド

**問題:** このアプリのAPIでは以下を使っています。

- GET
- POST
- PUT
- DELETE
- PATCH

これらの「HTTPメソッド」とは何ですか？
日常生活の例えで、それぞれの違いを説明してください。

**回答:**

HTTPメソッドは、リクエストで何をしたいかをサーバーに伝える動詞です。

GET：データを取得する
POST：新しいデータを作成する
PUT:データを丸ごと置き換える
PATCH：データの一部だけ変更する
DELETE：データを削除する

PUTとPATCHの違い：PUTは全項目を送って全部上書き、PATCHは変えたい項目だけ送ります。








## Q8. HTTPステータスコード

**問題:** サーバーからの返事には「ステータスコード」という3桁の数字が含まれます。

以下のコードはそれぞれ何を意味しますか？

- 200
- 201
- 400
- 404
- 500

**回答:**

ステータスコードは、サーバーが「処理の結果」を伝える３桁の数字です。最初の数字で大まかな種類がわかります。

200：OK 成功　リクエストが正常に処理された
201：Created 新しいデータの作成に成功した
400：Bad Request　リクエストの内容が不正　クライアント側の問題
404：Not Found　指定したデータやURLが存在しない
500：Internal ServerError　サーバー内部でエラーが発生した。サーバー側の問題

２XX=成功　４XX＝クライアント（送る側）のミス　５XX＝サーバー（受ける側）のミス


## Q9. JSONとは

**問題:** フロントエンドとバックエンド間でデータをやり取りする際に「JSON」という形式が使われています。

- JSONとは何ですか？
- なぜ広く使われていますか？

**回答:**

JSON(JavaScript Object Notation)は、データを人間にも機械にも読みやすいテキスト形式で表す書き方です。「キー：値」のペアで構成されます。

```json
{
  "id": 1,
  "name": "田中太郎",
  "age": 25,
  "hobbies": ["読書", "映画"]
}
```

なぜ広く使われているか？
・読みやすい：人間が見て理解しやすい
・言語に依存しない：JavaScript ,Python ,Javaなどほぼ全ての言語で扱える
・JavaScriptと相性が良い：ブラウザ上でそのまま変換して使える
・構造化できる：配列や入れ子のデータも表現できる

フロントエンドとバックエンドが別の言語で作られていても、JSONという共通語でやり取りできるのが大きな利点です。


## Q10. APIとは

**問題:** このアプリではフロントエンドがバックエンドのAPIを呼び出してデータを取得しています。

**回答:**

- APIとは何ですか？
Application Programming Interfaceの略
ソフトウェア同士がやり取りするための「窓口」「取り決め」です。

レストランの例えでは、お客さん（フロントエンド）はメニュー（API)を見て注文します。厨房（バックエンド）の中には入りません。メニューに載っている注文の仕方だけが許可されています。

- なぜ直接データベースにアクセスしないのですか？
いくつか理由はあります。

・セキュリティの問題：DBの接続情報がブラウザに露出すると、誰でもデータを盗んだり消したりしてしまう。

・権限管理：APIで「誰が何をできるか」（ログイン）を制御できる。

・データの検証：APIが不正なデータを弾き、DBの整合性を守れる。

・変更への強さ：DBの構造を変えても、APIの形が同じならフロントエンドを修正しなくて良い。

・再利用性：Web,スマホアプリなど複数のフロントエンドが同じAPIを使える。







## Q11. CORSとは

**問題:** フロントエンド（5173）からバックエンド（8080）にアクセスする際、「CORS」という仕組みが関係します。

CORSとは何のためにありますか？

**回答:**

CORS（Cross -Origin　Rescure Sharing)は、ブラウザが「別のオリジンのサーバー」へのアクセスを安全に制御する仕組みです。

オリジンとは、「プロトコル＋ドメイン＋ポート番号」の組み合わせです。
・フロントエンド：http://localhost:5173
・バックエンド　：http://localhost:8080

ポートが違うので、ブラウザはこれを「別オリジン」とみなします。

CORSが何のためにあるのか？というと

ブラウザには「同一オリジンポリシー」という安全機能があり、デフォルトでは別オリジンへのリクエスト結果をJavaScriptに読ませません。これは悪意あるサイトがログイン中のユーザーになりすまして、別サイトのデータを勝手に読むのを防ぐためです。

しかし、正常な連携まで止まると困るので、CORSがサーバが「このオリジンからのアクセスは許可する」と明治できるようにしています。

動き方はこうです
１　ブラウザがバックエンドにリクエストを送る　Origin ;http://localhost:5173

２　バックエンドが　 Access~contlol-Allow -Origin：http://localhost:5173　を返す

３　ブラウザが許可されたと判断し、JavaScriptにレスポンスを返す

許可がなければ、コンソールに「CORS policyによりブロックされました」とエラーが出ます。

## Q12. クライアントとサーバー

**問題:** 「クライアント」と「サーバー」とは何ですか？

このアプリの構成の中で、それぞれどれがクライアントでどれがサーバーですか？

- ブラウザ
- バックエンド
- データベース

**回答:**

クライアント：サービスを要求する側

サーバー：要求を受けて処理し、結果を返す側

この２つは、通信における役割を表しています。

ブラウザは、クライアントでバックエンドにAPIリクエストを送ります。

バックエンドは、立場が２つありブラウザから見るとサーバー、データベースから見るとクライアントです。ブラウザの要求を受けて処理し、応答を返します。

データベースは、サーバーでバックエンドからのSQLを受けて、データを返します。

## Q13. フロントエンドとバックエンド

**問題:** 「フロントエンド」と「バックエンド」の違いを説明してください。

このアプリではそれぞれ何を担当していますか？

**回答:**
フロントエンド　動く場所はユーザーのブラウザです。見た目や操作の役割を果たし、技術としてはReact,HTML \CSS,Javascriptを使います。ユーザーには見えます。

バックエンド　　動く場所はサーバーです。データ処理やルールの保存の役割を果たします。SpringBootやJavaを使います。ユーザーには見えません。

このアプリでは
・フロントエンド：5173 タスク一覧の呼び出しや入力フォーム、ボタン、APIの呼び出し、レスポンスの画面反映などを担当している。

・バックエンド：8080 リクエストの受付　入力チェック　ビジネスロジック　DBへの保存・取得、JSONで結果を返すなどを担当している。


## Q14. 3層構造

**問題:** このアプリは

- フロントエンド
- バックエンド
- データベース

の3層構造です。

なぜこのように役割を分けるのですか？

1つのプログラムですべてをやらない理由を説明してください。

**回答:**

理由は５つあります。

１　責任が明確になる　画面はフロント、処理はバック、保存はDB。どこを直せば良いかわかりやすい

２　変更の影響を小さくできる　デザインを変えてもバックエンドは無関係、DBを変えても画面は無関係など余計な手間をかけずに開発できる。

３　担当を分担できる　フロントとバックで並行して開発できる

４　再利用できる　同じバックエンドを、WEBアプリ・スマホアプリ両方から使える

５　セキュリティ　DBに直接アクセスできるのはDBだけ。パスワードや重要なルールをブラウザ側に置かずに済む。DBをブラウザから直接触らせるのは非常に危険である

１つのプログラムにまとめてしまうと

・コードが巨大で複雑になり、修正が難しい

・一部の変更が全体に影響してバグが出やすい

・チーム開発がしにくい

・セキュリティ面でも危険

といったデメリットがあるためです。

## Q15. データの流れ

**問題:** ユーザーが「新しいタスクを作成」ボタンを押してから、

- データベースに保存される
- 画面に反映される

までの流れを順を追って説明してください。

**回答:**

１【ブラウザ】操作を受け付ける
　　ユーザーがタイトルを入力し、ボタンをクリックするとReactのイベント処理が動く。

２【フロント】リクエストを送る
　Post http://localhost：8080/api/tasks
を送信。本文にはタスク内容をJSONで入れる。

３【CORS確認】
　別オリジンなので、ブラウザがバックエンドの許可を確認する。

４【バックエンド】リクエストを受け取る
Controllerが受信し、JSONをJavaのオブジェクトに変換する

５【バックエンド】処理する
Serviceで入力チェックなどのロジックを実行する。

６【バックエンド→DB】保存する
 Repository経由でSQLを実行する。

７【データベース】データを保存して結果を返す
保存後、自動採番されたIDなどを返す

８【バックエンド】レスポンスを返す

保存されたタスクをJSONにして、ステータスコード（200や201Created)と共に返す。

９【フロント】レスポンスを受け取る
JSONを受け取り、Reactのstateを更新する。

10【ブラウザ】画面に反映される
stateの変更により再描画され、新しいタスクが一覧に表示される。
